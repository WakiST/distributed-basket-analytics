# BasketNet - распределённая аналитика потребительской корзины

Учебный проект: TCP-брокер принимает задания от клиентов, распределяет между независимыми воркерами и возвращает результаты. Этот этап включает сетевое ядро, консольный и настольный клиенты, демонстрацию с тремя воркерами и тесты.

Нужен Python 3.10+, внешние Python-зависимости не требуются. Для настольного клиента нужен Tkinter: он входит в стандартный установщик Python для Windows; в Linux может потребоваться пакет `python3-tk`.

## Быстрый запуск

```shell
python run_demo.py
```

В Windows также можно открыть `start_demo.bat`. Запускаются брокер, три отдельных процесса-воркера и графический клиент. В демонстрации задания имеют задержку 0,5 секунды, чтобы были видны состояния. При закрытии окна процессы демонстрации останавливаются, журналы сохраняются локально в `logs/`.

В клиенте выберите операцию, задайте JSON и приоритет 0-9, отправьте задание. Доступны результат, история событий и мониторинг воркеров. Можно открыть примеры из `examples/`, сохранить результат или идентификатор задания с токеном.

Проверка без окна:

```shell
python run_demo.py --headless
```

Она выполняет все семь операций через реальные отдельные процессы. Не запускайте несколько демонстраций одновременно: используются порты 9000-9003.

## Реализованные возможности

| Возможность | Реализация |
|---|---|
| Задания и результаты | TCP, JSON Lines в UTF-8, кадр не более 2 МиБ |
| Приоритеты | 0-9; больший приоритет первым, FIFO при равенстве |
| Подтверждение | ACK с результатом; проверка исполнителя и идентификатора попытки |
| Повторная выдача | При разрыве TCP, пропаже heartbeat или таймауте ACK; другому ID воркера |
| Состояние воркеров | UDP heartbeat и мониторинг брокера |
| Уведомления | Отдельное TCP-соединение на порту 9002, история и версии событий |
| Параллельная работа | Многопоточный брокер и независимые процессы-воркеры |

Операции: `sum`, `sort`, `hash`, `count_words`, `basket_affinity`, `fib`, `factorial`. Сумма поддерживает чек со скидками; сортировка - ранжирование товаров по числовому полю; анализ пар - support, confidence и lift. Денежные расчёты используют Decimal, большие целые возвращаются строками для сохранения точности.

## Компоненты по отдельности

В разных терминалах:

```shell
python -m basketnet.broker
python -m basketnet.worker --id worker-1
python -m basketnet.worker --id worker-2
python -m basketnet.worker --id worker-3
python -m basketnet.gui
```

Один воркер тоже поддерживается: достаточно одной команды `basketnet.worker`. Для демонстрации переназначения после отказа нужен другой доступный ID воркера.

Консольный клиент:

```shell
python -m basketnet.client submit sum --data "[10,20,30]" --priority 5 --save task-demo.json --wait
python -m basketnet.client status task-demo.json
python -m basketnet.client watch task-demo.json
python -m basketnet.client monitor
```

## Несколько компьютеров

На серверном ПК:

```shell
python -m basketnet.broker --host 0.0.0.0
```

Воркеры можно оставить на этом ПК. На другом компьютере запустите клиент, подставив LAN-адрес сервера:

```shell
python -m basketnet.gui --host 192.168.1.10
```

Для отдельного ПК-воркера:

```shell
python -m basketnet.worker --host 192.168.1.10 --id remote-worker
```

У каждого воркера уникальный ID. На сервере разрешите в брандмауэре TCP 9000, 9001, 9002 и UDP 9003 для доверенной локальной сети. По умолчанию брокер слушает только 127.0.0.1. Клиентам на других ПК потребуется копия программы и Python; веб-доступ будет опубликован следующим этапом.

## Проверки

```shell
python -m unittest tests.test_tasks tests.test_network -v
python -m tests.gui_smoke
```

Сетевые тесты используют настоящие loopback-соединения и свободные порты. Проверяются приоритеты и FIFO, параллельные воркеры, разрыв TCP, UDP-таймаут, отсутствие ACK при живом heartbeat, переназначение другому ID, исчерпание попыток, устаревшие ACK, подписки, токены и некорректные сообщения. Для GUI-проверки нужен Tkinter; она работает со скрытым тестовым окном.

## Документация и ограничения

[Папка документации](docs/README.md) содержит описание протокола и Word-файл первого раздела курсовой записки с источниками.

Очередь и результаты находятся в памяти брокера и теряются при его перезапуске. Завершённые задания удаляются через час по умолчанию. Воркеры переподключаются, GUI восстанавливает подписки после временного сетевого разрыва.

Гарантия исполнения - at least once: при сбое вычисление может повториться; принимается результат только актуальной попытки. Операции не изменяют внешние данные. Система предназначена для доверенной локальной сети: TLS, резервный брокер и долговечная очередь не реализованы. Для доступа к конкретному заданию нужен его токен; отправка заданий и регистрация воркеров не защищены учётными записями.

Веб-магазин, аккаунты, купоны и постоянная история заказов остаются следующим этапом публикации.
