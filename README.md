# BasketNet - распределённая аналитика потребительской корзины

Учебная программа по теме «Распределённая сетевая система сбора, агрегации транзакций и аналитической обработки потребительской корзины».

**Python 3.10+**, стандартная библиотека, без pip-зависимостей. На компьютере разработки проверено с Python 3.12 / Windows. Для графического клиента нужен Tkinter (входит в стандартный установщик Python для Windows; на Linux может потребоваться пакет `python3-tk`).

## Быстрый запуск сайта

Короткая инструкция для нескольких компьютеров: [START_NETWORK.md](START_NETWORK.md).

```powershell
python run_web.py
```

Или откройте `start_web.bat`. Запускаются брокер, **три воркера** и веб-сервер. На своём ПК откройте `http://127.0.0.1:8088`, на другом ПК в той же сети - `http://IP-адрес-сервера:8088`. Клиенту нужен только браузер. Разрешите входящий TCP 8088 на серверном ПК из вашей доверенной локальной сети. Для остановки всех компонентов нажмите `Ctrl+C` в терминале запуска.

Другой порт: `python run_web.py --port 8090`. Один воркер: `python run_web.py --workers 1`. Задержка для демонстрации параллелизма: `python run_web.py --worker-delay 3`. Не запускайте `run_web.py` одновременно с `run_demo.py`: они используют одинаковые порты брокера.

Сайт работает как учебный магазин: открытый каталог, поиск, категории, распродажи, вход для добавления в корзину, личные купоны, оформление заказа и история с электронными чеками. Расчёт заказа выполняется через TCP-брокер в два этапа: `sum` для цен и скидок, затем `hash` для контрольной суммы чека. Оплата и доставка не выполняются.

У администратора отдельный раздел: редактирование каталога и скидок, выдача личных купонов, все заказы, аналитика покупок, мониторинг воркеров и генератор заказов. Все семь исходных операций доступны в лаборатории администратора, включая `fib` и `factorial`. В генераторе задаются количество заказов, окно одновременной обработки, CPU-нагрузка и диапазон приоритетов. Подробности и сценарий демонстрации: [SHOP_GUIDE.md](SHOP_GUIDE.md).

При первом запуске создаётся аккаунт `admin`, случайный пароль записывается на сервере в `data/shop.sqlite3.admin.txt`. Можно задать `BASKETNET_ADMIN_PASSWORD` в окружении **перед первым запуском новой базы**. Последующие запуски пароль не меняют. Аккаунты, корзины, заказы, купоны и чеки сохраняются в SQLite `data/shop.sqlite3`; путь можно изменить `--database`. Файл базы и данные входа исключены из Git. После перезапуска сайта требуется повторный вход.

Сеансы и лабораторные расчёты администратора хранятся в памяти сайта; постоянная история заказов хранится отдельно в SQLite. Лимиты лаборатории: 100 заданий на сеанс, до 20 активных. До четырёх вкладок SSE на сеанс; неактивные сеансы без расчётов могут удаляться через час. Заказы возобновляют подписку при перезапуске сайта; после перезапуска брокера потерянные задания получают ошибку, завершённые чеки остаются в базе.

## Запуск настольного клиента

Откройте терминал в папке проекта:

```powershell
python run_demo.py
```

Либо дважды щёлкните **start_demo.bat**. Запустятся брокер, три отдельных процесса-воркера и графический клиент. В демонстрации воркеры задерживают каждое задание на 0,5 секунды, чтобы были видны переходы статуса. При закрытии окна запущенные демонстрацией процессы останавливаются. Их журналы находятся в `logs/`.

В окне выберите операцию, задайте приоритет от 0 до 9, отредактируйте пример JSON и нажмите «Отправить задание». Вверху расположены карточки счётчиков, слева - ввод данных, справа - задания и их детали. На вкладке «Результат» расчёт показан с русскими пояснениями, на вкладке «JSON» доступны полные исходные данные результата. Рядом находятся события задания и мониторинг воркеров. Данные из `examples/` можно открыть кнопкой «Открыть JSON» после выбора соответствующей операции. ID с токеном и результаты можно сохранить в файлы.

Счётчики показывают все задания брокера; таблица «Мои задания» - задания, отправленные из текущего окна. Изменение адреса применяется к новым запросам; подписки уже отправленных заданий остаются подключены к исходному брокеру.

Проверка демонстрации без открытия окна:

```powershell
python run_demo.py --headless
```

Она запускает отдельные процессы, отправляет все семь типов задач, проверяет завершение и освобождает процессы. Порты 9000-9003 должны быть свободны. Не запускайте одновременно несколько экземпляров `run_demo.py`.

## Отдельный запуск компонентов

Запустите команды в разных терминалах:

```powershell
python -m basketnet.broker
```

```powershell
python -m basketnet.worker --id worker-1
```

```powershell
python -m basketnet.worker --id worker-2
```

```powershell
python -m basketnet.gui
```

Для нескольких компьютеров запустите брокер с `--host 0.0.0.0`. На других компьютерах используйте LAN-адрес брокера:

```powershell
python -m basketnet.worker --host 192.168.1.10 --id node-2
python -m basketnet.gui --host 192.168.1.10
```

У каждого воркера должен быть уникальный `--id`; без параметра уникальный ID генерируется автоматически. На машине брокера брандмауэр должен разрешать входящие TCP 9000, 9001, 9002 и UDP 9003. Воркеры узнают UDP-порт при регистрации, а клиент узнаёт порт подписки в ответе на отправку задания. Для нестандартного клиентского TCP-порта используется `--port` у клиента и `--client-port` у брокера.

## Доступ через браузер и локальную сеть

В проекте доступны сайт, настольное приложение Tkinter и консольный клиент. Сайт запускается отдельно командой `python -m basketnet.web --host 0.0.0.0 --broker-host АДРЕС_БРОКЕРА`, по умолчанию на TCP 8088. Веб-сервер отправляет задания брокеру по TCP 9000 и подписывается на статусы по TCP 9002. Для браузера уведомления передаются через отдельное HTTP-соединение Server-Sent Events (SSE), работающее поверх TCP. Браузер не подключается непосредственно к TCP-протоколу брокера. Статические ресурсы сайта локальные, внешние сервисы и CDN не используются.

По умолчанию брокер слушает `127.0.0.1`: подключиться можно только с того же компьютера. При запуске с `--host 0.0.0.0` брокер принимает соединения на всех IPv4-интерфейсах; в локальной сети другие компьютеры могут использовать клиент BasketNet при наличии сетевой доступности и разрешений брандмауэра. Программа сама не подключает посторонних к вашей сети и не настраивает роутер. Учётных записей для ограничения отправки заданий нет: любой узел, имеющий сетевой доступ к порту брокера, может отправить задание. Для просмотра конкретного результата необходим его токен.

## Реализованные требования

| Требование | Реализация |
|---|---|
| Приём заданий и возврат результатов | TCP, JSON Lines; API, CLI, настольный и веб-клиенты |
| Приоритетная очередь | `heapq`, приоритет 9 выше 0, FIFO при равенстве |
| Параллельное выполнение | Несколько отдельных процессов-воркеров, в том числе на разных компьютерах |
| Многопоточный брокер | Потоки приёма соединений, обработчики подключений, планировщик, UDP-приёмник и watchdog |
| Подтверждение выполнения | ACK с результатом и уникальным ID попытки |
| Повторная выдача | При разрыве TCP, таймауте задачи или UDP heartbeat - другому worker_id |
| Обнаружение мёртвых узлов | UDP heartbeat с токеном сессии; монотонные часы |
| Независимые уведомления | Выделенный TCP-порт, история переходов и восстановление подписки |
| Мониторинг | Очередь, счётчики задач, узлы idle / busy / dead, давность heartbeat и причина отключения |

Планировщик назначает первому свободному подходящему узлу задание с наивысшим приоритетом. Выполняющееся задание не прерывается ради нового срочного. Если нет другого узла для повторной попытки, задача остаётся в очереди до его появления. Переподключившийся узел может выполнять другие задания.

## Операции и формат данных

| Операция | Вход `data` | Результат |
|---|---|---|
| `sum` | `[10, 20, 5]` | `35` |
| `sum` с чеком | Объект `items` и необязательный `discount_percent`; пример `examples/receipt.json` | Сумма до скидок, скидки по позициям и чеку, итог |
| `sort` | Массив чисел или `{ "items": [...], "key": "margin", "reverse": true }` | Отсортированный массив; пример `examples/products.json` |
| `hash` | JSON-строка | Название алгоритма и SHA-256 текста UTF-8 |
| `count_words` | JSON-строка | Частоты слов без учёта регистра, общее и уникальное количество |
| `basket_affinity` | Массив чеков или объект `baskets`, `min_support`, `top_k`; пример `examples/baskets.json` | Наиболее частые пары с support, confidence в обоих направлениях и lift |
| `fib` | Целое N от 0 до 10 000 | F(N), F(0)=0, F(1)=1; десятичная строка |
| `factorial` | Целое N от 0 до 1 000 | N!, 0!=1; десятичная строка |

Денежные вычисления используют `Decimal` и округление до сотых `ROUND_HALF_UP`. Сначала округляется стоимость позиции (`price × quantity`), затем скидка позиции; общая скидка чека применяется к сумме после скидок позиций. Денежные результаты возвращаются строками, например `"7.72"`, для точного представления. Большие целые также возвращаются строками, чтобы клиенты не теряли точность.

Для affinity один товар учитывается не более одного раза в чеке. Для пары A, B при числе чеков M:

- `support = count(A,B) / M`;
- `confidence_a_to_b = count(A,B) / count(A)`;
- `confidence_b_to_a = count(A,B) / count(B)`;
- `lift = count(A,B) × M / (count(A) × count(B))`.

Пары сортируются по числу совместных покупок, затем по названиям. `top_k` по умолчанию 20, максимум 1000. Пустые чеки входят в M. `count_words` анализирует текст названий/покупок; структурированный анализ чеков выполняется через `basket_affinity`.

Проверка данных выполняется до постановки в очередь и повторно на воркере. Ограничения защищают учебный стенд от чрезмерных вычислений: массивы до 10 000 элементов, текст для hash до 500 000 байт, для частотного анализа до 100 000 символов, до 100 товаров в одном чеке и до 20 000 позиций в наборе для affinity. Данные задания - до 1 500 000 байт; TCP-кадр - до 2 МиБ.

## Командный клиент

```powershell
python -m basketnet.client submit sum --data '[10,20,30]' --priority 9 --save task.json --wait
python -m basketnet.client submit sum --file examples/receipt.json --wait
python -m basketnet.client submit sort --file examples/products.json --wait
python -m basketnet.client submit basket_affinity --file examples/baskets.json --priority 5 --wait
python -m basketnet.client submit fib --data 100 --wait
python -m basketnet.client submit factorial --data 50 --wait
python -m basketnet.client status task.json
python -m basketnet.client watch task.json
python -m basketnet.client monitor
```

Для текстовых операций удобно передавать файл с JSON-строкой, например содержимым `"молоко хлеб молоко"`. Это исключает различия экранирования кавычек в терминалах.

Ответ на `submit` содержит `task_id` и `task_token`; сохраните их для дальнейшего чтения статуса и подписки. `--wait` слушает отдельное TCP-соединение и выводит события до результата; `--timeout` задаёт лимит ожидания клиента (по умолчанию 60 секунд). Прерывание клиента не отменяет задачу.

## Демонстрация отказоустойчивости и приоритетов

1. **Приоритеты:** запустите только брокер. Отправьте несколько заданий без `--wait` с приоритетами 0, 9, 5, 9. `monitor` покажет порядок 9, 9, 5, 0. Запустите один воркер с `--delay 2`; журнал брокера покажет тот же порядок назначения.
2. **Параллелизм:** подключите два воркера с `--delay 3`, отправьте несколько заданий. В мониторинге два узла одновременно находятся в `busy`.
3. **Обрыв TCP:** запустите воркер с `--id worker-1 --delay 15` и отправьте задание. Когда оно выполняется, остановите процесс воркера через Ctrl+C. Запустите `worker-2`; задача завершится с `attempt: 2`.
4. **Нет heartbeat:** запустите `python -m basketnet.worker --id no-pulse --no-heartbeat --no-reconnect --delay 15`. Отправьте задание. Примерно через 5 секунд в журнале появится `Таймаут UDP heartbeat`, а задача вернётся в очередь. Подключите воркер с другим ID.
5. **Нет ACK при работающем heartbeat:** запустите брокер с `--task-timeout 3`; воркер - с `--id slow --delay 15 --no-reconnect`. После таймаута подключите быстрый воркер с другим ID. Задача будет повторена.

Параметры брокера: `--heartbeat-timeout 5`, `--task-timeout 30`, `--max-attempts 3`, `--retention 3600`, `--max-tasks 10000`. После исчерпания попыток статус - `error`; ошибка вычисления также сразу даёт `error`.

## Проверка

```powershell
python -m unittest discover -s tests -v
python run_demo.py --headless
python run_web.py --check
```

Тесты проверяют расчёты, валидацию, TCP-фрейминг, приоритеты/FIFO, несколько клиентов и воркеров, отдельный канал событий, восстановление истории, отказ TCP, UDP-таймаут, ACK-таймаут, ограничение повторов, выбор другого узла, отказ от устаревших и повторных ACK, защиту результата токеном и удаление старых результатов. Сетевые тесты используют настоящие локальные TCP/UDP-сокеты с автоматически выделенными портами.

Дополнительная проверка графического клиента при наличии Tkinter и графической сессии: `python -m tests.gui_smoke`. Она проверяет отправку через GUI, получение событий, вывод результата и мониторинг воркера в скрытом тестовом окне.

Тесты `tests/test_web.py` проверяют HTTP, отдельный поток SSE, историю после обновления страницы, изоляцию сеансов, валидацию запросов, недоступность брокера и точность больших целых в браузере. Команда `run_web.py --check` запускает отдельные процессы и выполняет все семь операций через HTTP. Для неё нужны свободные порты стенда; после проверки процессы останавливаются. На веб-сервере Tkinter не требуется.

`tests/test_shop.py` проверяет права ролей, вход и выход, хеширование паролей, сохранность SQLite, серверные цены, скидки, одноразовые купоны, повторное оформление, изоляцию заказов, SSE заказов, генератор, ограничения параллельности, остановку серии, приоритеты и восстановление подписки с переназначением другому воркеру. Проверка `run_web.py --check` использует отдельную временную базу и не меняет покупки магазина.

## Структура и границы проекта

```text
basketnet/
  broker.py       Брокер и планировщик
  worker.py       Вычислительный узел и heartbeat
  client.py       API и консольный клиент
  gui.py          Графический клиент и мониторинг
  web.py          HTTP-сервер и передача уведомлений в браузер
  shop.py         SQLite, аккаунты, корзины, заказы и генератор
  web_static/     HTML, CSS и JavaScript сайта
  samples.py      Общие примеры для клиентов
  protocol.py     Общий TCP-фрейминг
  tasks.py        Алгоритмы и проверка входных данных
examples/         Примеры чеков и корзин
tests/            Алгоритмические и сетевые тесты
docs/PROTOCOL.md  Подробное описание сетевого протокола
run_demo.py       Управление локальными процессами демонстрации
start_demo.bat    Запуск в Windows двойным щелчком
run_web.py        Брокер, три воркера и сайт одной командой
start_web.bat     Запуск сайта в Windows двойным щелчком
START_NETWORK.md Короткая инструкция для нескольких компьютеров
SHOP_GUIDE.md    Магазин, администратор и демонстрация нагрузки
```

Очередь и результаты брокера находятся в памяти. Завершённые задания брокера удаляются через час по умолчанию; его перезапуск сбрасывает очередь. Воркеры автоматически переподключаются, клиент GUI восстанавливает подписки после сетевого разрыва. После перезапуска самого брокера восстановить потерянное задание нельзя. Аккаунты и история заказов сайта сохраняются отдельно в SQLite.

Гарантия исполнения - **at least once**: вычисление при сбое может повториться, но брокер принимает только результат актуальной попытки. Операции воркеров не изменяют внешние данные. Это учебный стенд для доверенной локальной сети: без TLS и резервного брокера. Права сайта не распространяются на отдельный TCP-протокол брокера. Встроенные ограничения памяти и входных данных не заменяют защиту публичного сервиса.

Подробности сообщений: [docs/PROTOCOL.md](docs/PROTOCOL.md).
