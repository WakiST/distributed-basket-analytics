# BasketNet: короткая инструкция запуска

## 1. Основной вариант: твой ПК - сервер и 3 воркера, другой ПК - браузер

Оба компьютера должны быть в одной локальной сети. На твоём ПК нужны Python 3.10+ и полная локальная папка проекта. На клиентском ПК ничего устанавливать не нужно.

**На твоём ПК** открой терминал в папке проекта и выполни:

```powershell
python run_web.py
```

Или дважды щёлкни `start_web.bat`. Команда запускает брокер, **три воркера** и сайт. Не закрывай терминал. Остановка всех компонентов: `Ctrl+C`.

Узнай IPv4-адрес своего Wi-Fi/Ethernet через `ipconfig`. Например, адрес оказался `192.168.1.10`.

**На клиентском ПК** открой браузер и введи:

```text
http://192.168.1.10:8088
```

Замени адрес на свой. На твоём ПК сайт доступен по `http://127.0.0.1:8088`.

Каталог доступен без входа. При добавлении товара сайт предложит войти или зарегистрироваться. После регистрации доступен личный купон `WELCOME10`. Собери корзину, выбери купон и оформи учебный заказ. В «Моих заказах» автоматически появятся статус, сумма и электронный чек. Реальной оплаты нет.

Для администратора: логин `admin`, случайный пароль первого запуска находится в `data/shop.sqlite3.admin.txt` на серверном ПК. После входа появится вкладка «Администратор» с товарами, купонами, заказами, аналитикой и генератором нагрузки. Данные входа не нужно отдавать покупателям. Подробнее: [SHOP_GUIDE.md](SHOP_GUIDE.md).

На серверном ПК разреши в брандмауэре входящий **TCP 8088** из вашей доверенной локальной сети. Остальные порты в этом варианте используются только внутри твоего ПК. Программа не изменяет брандмауэр и роутер автоматически.

Для одного воркера: `python run_web.py --workers 1`. Для наглядной демонстрации очереди и параллелизма: `python run_web.py --worker-delay 3`.

## 2. Все компоненты на отдельных ПК

На ПК с брокером, воркером и сайтом нужны Python и полная папка проекта. На клиентском ПК нужен только браузер. Во всех командах замени IP-адреса примера своими.

| Где | Что запустить в терминале из папки проекта |
|---|---|
| ПК 1: брокер, IP `192.168.1.10` | `python -m basketnet.broker --host 0.0.0.0` |
| ПК 2: первый воркер | `python -m basketnet.worker --host 192.168.1.10 --id worker-1` |
| ПК 3: сайт, IP `192.168.1.30` | `python -m basketnet.web --host 0.0.0.0 --broker-host 192.168.1.10` |
| ПК 4: клиент | Открыть `http://192.168.1.30:8088` в браузере |

Дополнительные воркеры можно запускать на ПК 2 в отдельных терминалах или на других компьютерах: те же команды с `--id worker-2` и `--id worker-3`. У каждого воркера свой уникальный ID.

На ПК 1 разреши входящие **TCP 9000, 9001, 9002 и UDP 9003** из вашей локальной сети. На ПК 3 разреши **TCP 8088**. Клиентский браузер подключается к ПК с сайтом, а не напрямую к брокеру.

Если сайт и брокер на одном ПК, запускай сайт без `--broker-host`; по умолчанию используется `127.0.0.1`. В этом раздельном сценарии не запускай `run_web.py`: он создаёт собственный комплект локальных компонентов.

## 3. Что важно для демонстрации

- Один воркер работает, но выполняет задачи последовательно. Для параллельного выполнения и повторной выдачи другому узлу нужны минимум два воркера с разными ID. После отказа единственного воркера задача ожидает другого узла.
- Остановка процесса одного воркера не останавливает брокер и остальных исполнителей. Для удобной демонстрации отказа используй отдельные команды из раздела 2 в разных терминалах одного ПК: тогда конкретный воркер можно остановить через `Ctrl+C` в его терминале.
- Если страница не открывается, проверь адрес, общую сеть, работающий сервер и TCP 8088: `Test-NetConnection 192.168.1.10 -Port 8088`. Гостевой Wi-Fi может запрещать связь между устройствами.
- Если сайт открыт, но брокер недоступен, проверь запуск брокера и адрес `--broker-host`. Если задача в очереди, проверь наличие свободного воркера.
- Аккаунты, корзины, купоны, заказы и чеки сохраняются в `data/shop.sqlite3` на ПК с сайтом. После перезапуска сайта нужно войти заново. Не удаляй базу, если хочешь сохранить покупки.
- Очередь брокера хранится в памяти: перезапуск самого брокера сбрасывает незавершённые задания. История магазина остаётся, потерянное задание отмечается ошибкой. При перезапуске только сайта он восстанавливает подписки по сохранённым токенам.
- Это стенд для доверенной локальной сети с аккаунтами сайта, без HTTPS. TCP-протокол брокера по-прежнему предназначен для доверенных узлов. Публиковать его напрямую в интернет не требуется.
- На GitHub пока находится только первая часть проекта. Для запуска используй полную локальную папку.
