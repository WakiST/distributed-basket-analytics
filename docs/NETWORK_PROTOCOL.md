# Сетевой протокол

Все TCP-сообщения - JSON в UTF-8, одно сообщение на строку (`\n`). Максимальный размер сообщения - 2 МиБ. Версия протокола - 1. Все временные метки - Unix time в секундах.

По умолчанию брокер слушает 127.0.0.1:

| Порт | Транспорт | Назначение |
|---|---|---|
| 9000 | TCP | Отправка заданий, запрос результата, мониторинг |
| 9001 | TCP | Регистрация воркеров, выдача заданий, ACK |
| 9002 | TCP | Отдельный канал подписки на изменения статуса |
| 9003 | UDP | Heartbeat воркеров |

## Клиент

`{"type":"submit","operation":"sum","data":[10,20],"priority":5}`

Ответ содержит `task_id` и секретный `task_token`. Их необходимо сохранить для чтения результата и подписки. Приоритет - целое число от 0 до 9; большее значение означает более срочное задание. При одинаковом приоритете действует FIFO. Уже выполняющиеся задания не вытесняются.

`{"type":"status","task_id":"…","task_token":"…"}` - текущее состояние и результат.

`{"type":"monitor"}` - очередь, состояния воркеров и счётчики заданий без секретных токенов.

## Подписки

На отдельном TCP-порту клиент передаёт `{"type":"subscribe","task_id":"…","task_token":"…","after_version":0}`. Брокер сначала отправляет сохранённые события с большей версией, затем новые события. Последовательность статусов: `queued → running → completed/error`. При повторной выдаче: `running → queued → running`. На каждый переход растёт `version`. Финальное событие содержит результат либо описание ошибки. Переподключение возможно с последней прочитанной версией; история ограничена, поэтому при пропуске старых событий клиент получает актуальное состояние.

## Воркеры

Воркер отправляет `{"type":"register","worker_id":"…","protocol":1}` и получает параметры heartbeat, UDP-порт и случайный `session_token`. Повторная регистрация уже подключённого worker_id отклоняется.

Брокер выдаёт `{"type":"task","task_id":"…","attempt_id":"…","operation":"…","data":…, "attempt":1}`. Один воркер одновременно выполняет одно задание.

После вычисления воркер отправляет `{"type":"ack","task_id":"…","attempt_id":"…","ok":true,"result":…}`; при ошибке - `ok:false,error:"…"`. ACK одновременно подтверждает окончание работы и доставляет результат. Брокер отвечает `ack_received` с полем `accepted`. ACK принимается только от текущего владельца задания и только для текущего `attempt_id`.

UDP heartbeat: `{"type":"heartbeat","worker_id":"…","session_token":"…"}`. Таймер отсчитывается по монотонным часам. Пакеты чужой или старой сессии игнорируются.

## Отказы и гарантии

При разрыве TCP, пропаже heartbeat или истечении времени выполнения брокер отключает сессию воркера и возвращает незавершённое задание в очередь. Повторная попытка сохраняет исходные приоритет и FIFO-позицию и назначается узлу с другим worker_id. Пока другого узла нет, задание ожидает в очереди; доступный воркер может выполнять следующие подходящие задания. Число попыток ограничено; после исчерпания задача переходит в `error`. Ошибки входных данных и вычислений повторно не исполняются.

Гарантия исполнения - **at least once**: при сбое одно вычисление может фактически произойти несколько раз. Внешних побочных эффектов у предусмотренных операций нет; брокер принимает только один актуальный результат.

Очередь и результаты хранятся в оперативной памяти; перезапуск брокера их сбрасывает. Протокол рассчитан на доверенную учебную локальную сеть: TLS и учётных записей нет. Токены закрывают доступ к чужому результату, но не заменяют шифрование и полноценную аутентификацию. Для работы между компьютерами брокер запускается с `--host 0.0.0.0`, клиенты и воркеры используют его LAN-адрес.
