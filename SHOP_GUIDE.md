# Магазин и генератор нагрузки BasketNet

## Быстрый старт

`python run_web.py` запускает сайт, брокер и **3 отдельных процесса-воркера**. Открой `http://127.0.0.1:8088`. Клиенты с другого ПК заходят на `http://IP-СЕРВЕРА:8088`. Инструкция для разных компьютеров: [START_NETWORK.md](START_NETWORK.md).

Покупателю не нужно устанавливать Python. Каталог открыт всем. Для корзины нужно зарегистрироваться (логин из 3-32 букв, цифр или `_`, пароль 8-128 символов) либо войти. После входа товар, на котором нажали «+», автоматически добавляется в корзину.

## Покупатель

1. Выбрать категорию, найти товар или открыть товары со скидкой.
2. Добавить товары, открыть корзину и изменить количество.
3. Выбрать личный купон. При регистрации выдаётся `WELCOME10` на 10%.
4. Нажать «Оформить заказ». В «Моих заказах» появятся состояния ожидания, очереди, выполнения, завершения или ошибки.
5. Скачать готовый электронный чек в JSON. Поле `sha256` - хеш UTF-8-байтов строки `fiscal_data` из этого файла. Он позволяет обнаружить изменение исходных данных чека; это учебная контрольная сумма, а не регистрация чека в фискальной системе.

Скидка товара округляется до копеек на всю строку (цена × количество). Затем один купон применяется к остатку. Купон зарезервирован за заказом с момента оформления, после ошибки освобождается. Это одноразовый купон **для каждого владельца**, а не один на всех покупателей. Цены, скидки и доступность берутся с сервера; подмена цены или приоритета в запросе покупателя не влияет на заказ. Обычный заказ имеет приоритет 3 и лёгкую нагрузку. Повтор одного запроса оформления с тем же ключом возвращает прежний заказ.

Деньги, доставка и реальные платежи в проекте не используются. Валюта отображения - BYN.

## Администратор

Логин: `admin`. При первом запуске случайный пароль записывается в `data/shop.sqlite3.admin.txt` рядом с базой. Не размещай этот файл в Git. При собственном `--database` имя файла будет `<путь-базы>.admin.txt`. Если перед созданием базы задана переменная `BASKETNET_ADMIN_PASSWORD`, используется её значение и файл с паролем не создаётся.

После входа появляется вкладка «Администратор». Право доступа проверяется сервером на каждом запросе.

- **Система и нагрузка**: общая очередь брокера, состояние воркеров, heartbeat, выполненные задания и генератор.
- **Все заказы**: реальные учебные покупки и, по отдельной галочке, тестовые. В карточке доступен журнал этапов `sum` и `hash`, назначений и повторных попыток.
- **Товары и купоны**: изменение цены, названия, категории, скидки и доступности товара; выдача купона конкретному логину. Уже оформленные заказы не меняются.
- **Аналитика и расчёты**: сопутствующие товары, частоты слов в названиях покупок, ранжирование каталога по цене. По умолчанию тестовые заказы исключены. Источник - последние 1 000 завершённых заказов. В лаборатории доступны все исходные операции с JSON, включая Фибоначчи и факториал, доступные только администратору сайта.

## Генератор

| Настройка | Что означает |
|---|---|
| Всего заказов: 1-200 | Размер одной серии |
| Одновременно: 1-30 | Сколько заказов серии одновременно допущено к брокеру, включая очередь и выполнение |
| Лёгкая нагрузка | Обычный расчёт чека и его хеш |
| Средняя нагрузка | Дополнительно 500 000 итераций PBKDF2-SHA256 в задании `sum` |
| Тяжёлая нагрузка | Дополнительно 2 000 000 итераций PBKDF2-SHA256 в задании `sum` |
| Смешанная нагрузка | Уровни чередуются между заказами |
| Приоритеты | Один приоритет у всех либо равномерное чередование целых значений в диапазоне 0-9 |

Дополнительный расчёт создаёт **реальную синтетическую нагрузку на CPU воркера**. Это измерительный инструмент, а не необходимая часть расчёта скидок. Сумма от него не меняется. Время зависит от ПК; точная длительность в секундах заранее не задаётся. Один заказ даёт два задания брокеру: сумму и хеш, поэтому счётчик заданий и число заказов различаются.

Больший приоритет обрабатывается раньше среди уже поступивших в очередь заданий. Уже выполняющееся задание не прерывается. При равенстве действует FIFO. Заказы, ожидающие подачи из-за ограничения окна, ещё не участвуют в очереди брокера.

Одновременно запускается одна серия. Кнопка «Остановить подачу» отмечает ещё не отправленные заказы ошибкой остановки; уже допущенные заказы завершаются. Новую серию можно начать после завершения активных заказов. Подача продолжается даже после закрытия вкладки администратора.

### Что показать на защите

1. Запустить 30 заказов, одновременно 12, смешанная нагрузка, приоритеты 0-9.
2. Показать трёх занятых воркеров, очередь и разные времена расчёта. Приоритет сравнивать у заданий, которые уже ждут, а не у тех, что ещё не поданы.
3. Повторить с одинаковым приоритетом для FIFO, затем с тяжёлой нагрузкой для более заметной очереди.
4. Для сравнения с одним воркером остановить стенд `Ctrl+C` и запустить `python run_web.py --workers 1`. Сравнивать одинаковые число заказов, нагрузку и окно; случайные составы корзин могут немного отличаться.
5. Для демонстрации отказа запускать компоненты отдельно в терминалах, остановить одного занятого воркера. Брокер выдаст его задание другому узлу. Одного воркера достаточно для работы, но для переназначения нужен другой ID воркера.

## Хранение и перезапуски

SQLite хранит пользователей (пароли хешированы с отдельной солью), каталог, корзины, купоны, серии, заказы, события и чеки. Не удаляй базу для обычного перезапуска. Сайт поддерживает один процесс веб-сервера на базу; SQLite-файл должен находиться на локальном диске ПК сайта.

Перезапуск только сайта требует нового входа, после чего история снова доступна. Для текущего заказа сайт восстанавливает TCP-подписку по сохранённому токену. Брокер хранит очередь в памяти: при его перезапуске незавершённое задание теряется и заказ получает ошибку. Заказ, ещё не отправленный брокеру, будет подан после запуска сайта. Если связь временно пропадает после отправки, сайт восстанавливает подписку. После ошибки покупатель может собрать и оформить новый заказ; списания денег нет.

Вычисления допускают повторное исполнение при сетевых сбоях, но не списывают деньги и не изменяют остатки. Между отправкой по TCP и записью токена в SQLite остаётся окно сбоя: при аварийной остановке расчёт может повториться, идентификатор заказа остаётся прежним.

Стенд предназначен для доверенной локальной сети. HTTP не шифрует пароли в сети, роли сайта не распространяются на отдельный TCP-протокол учебного брокера. Для полноценного публичного магазина нужны другие эксплуатационные меры; этот проект их не заявляет.
